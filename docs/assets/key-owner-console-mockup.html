JML 접속 키 관리 · 직접 구현 목업

상용·오픈소스 레퍼런스에서 가져올 기능과, 직접 만들 때의 모습

제품을 도입하지 않고 같은 수준의 기능을 자체 환경에 맞춰 만든다는 방향을 화면으로 그려 봤습니다. 아래 화면의 사람·키·건수는 모두 예시이며 확정 설계가 아닙니다.

모든 데이터는 가상의 예시입니다. 연결표 입력 경로, 재활성화 가능 여부 등은 확인 전이라 "(가정)"으로 표시했습니다. 파일럿은 메신저와 시트로 시작하고, 이 콘솔은 전용 UI를 검토할 때의 모습입니다.

2. 직접 만들 때의 흐름

강조한 칸이 새로 만드는 부분입니다. 앞단(인사 자료)과 뒷단(각 시스템 키 조회·회수)은 기존 것을 씁니다.

HR 시스템입·이·퇴사 일 배치
→
이벤트 판정퇴사 · 이동 구분

소유자 대응표토큰 소유자 ↔ 사번 (사번 연결표 경유)

처리 대기열회수 · 이관 요청 · 수동 처리

오회수 방지건수 경고 · 기록만 하는 모드
→
각 시스템키 회수 · 알림 · 기록
